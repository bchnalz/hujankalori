# Hujan Kalori

Mobile-first survival/endless **catcher** minigame for **LAPER**. The player moves
left/right to catch falling **activity** items (restore HP) and avoid **food**
items (drain HP). Built to be deployed as a **separate** Vercel project and
embedded into LAPER via iframe so it never affects production performance.

> Stack: **Phaser 3 + TypeScript + Vite**. Rendering is WebGL with Canvas
> fallback for smooth play on smartphone browsers.

## This iteration (first pass)

Implemented: **GAME-01** (core loop) and **GAME-02** (progressive difficulty),
on an **asset-driven** loader, with a **dummy data layer** so the game can be
reviewed before LAPER/Supabase integration.

Not yet implemented (next passes): tokens (GAME-03/04), points (GAME-05),
leaderboard (GAME-06), cosmetics + shop + rare drop (GAME-07/08/09), full
asset-driven cosmetics (GAME-10), and deployment wiring (GAME-11). See
[`docs/GDD.md`](docs/GDD.md) for the mapping.

## Quick start

```bash
npm install
npm run dev      # generates placeholder assets, then starts Vite on :5173
```

Open the printed URL on desktop or a phone on the same network. Drag anywhere to
move the player; on desktop you can also use the arrow keys.

## Sound & leaderboard

**Sound.** All SFX and the gameplay music are synthesized at runtime with the
Web Audio API (`src/audio/Sfx.ts`), so there are no audio files to load.
Browsers block audio until the first tap, so the game now opens on a **Start
screen** (`StartScene`) whose MULAI button unlocks audio and fires the opening
lightning strike. A mute button (top-left) is remembered per device.

**Leaderboard (no login).** At game over the player types **4-letter
initials**. Each initials keeps only its **best** score, on three boards:
**Hari Ini**, **Minggu Ini** (both on the WIB calendar, ISO weeks) and
**Semua** (all time). Data lives in **Vercel KV** (Upstash Redis) behind the
serverless function `api/leaderboard.ts`.

| Endpoint | Purpose |
|----------|---------|
| `GET /api/leaderboard?period=day\|week\|all&limit=15&name=ABCD` | Top scores + total players + that initials' rank |
| `POST /api/leaderboard` `{ action: "start" }` | Open a run session (called when "MULAI!" appears) |
| `POST /api/leaderboard` `{ name, score, sid }` | Submit; returns rank/total/best/top-10 for all three boards |

Anti-cheat:
- Survival time is accumulated from frame deltas, and the game **auto-pauses**
  when the tab/app is hidden, so time spent away never counts.
- Every run needs a single-use server session; a score longer than the real
  time since that session started (+3 s) is rejected (`score_mismatch`).
- `^[A-Z]{4}$` initials, offensive-initials blocklist, score range 1–3600 s,
  6 submissions and 30 run starts per IP per minute.

Redis keys: `hk:v2:all`, `hk:v2:w:<YYYY-Www>` (21-day TTL),
`hk:v2:d:<YYYY-MM-DD>` (3-day TTL), `hk:s:<sid>` (2-hour TTL). Scores from the
first version (`hk:lb`) are migrated into the all-time board automatically.

### Connecting Vercel KV
1. In the Vercel project: **Storage → Create Database → Upstash for Redis**
   (the current home of Vercel KV; the free plan is enough) and connect it to
   this project for all environments.
2. Vercel injects `KV_REST_API_URL` and `KV_REST_API_TOKEN` automatically
   (`UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` also work).
3. Redeploy. No code or dependency changes needed.

Until KV is connected, or when running plain `npm run dev` (Vite does not
serve `/api`), the game falls back to a **local per-device board** and shows
an "Offline" note. To test the real API locally use `vercel dev` after
`vercel env pull`.

## Notes

- Placeholder art is generated by `scripts/gen-placeholders.mjs` (pure Node, no
  extra deps) and is **gitignored**. Designers replace the files in
  `public/assets/` with real PNGs (see the asset spec).
- All gameplay tuning lives in `src/config/` — no logic changes needed to
  rebalance the game or add items.
